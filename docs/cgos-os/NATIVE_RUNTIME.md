# Native CGOS runtime

Package the existing graph runtime as a systemd service named cgosd. Keep the graph engine independent of systemd, the dashboard, transport and inference. A small service process owns the graph database, exposes a versioned API over a Unix socket, and ticks admitted graphs. Reuse Phase 1A graph validation and durable artifacts and Phase 1B attempt reconciliation and verified publication. The first service implementation must add a bounded admission queue, bounded worker I/O and restart tests across the daemon entry point.

1. On first boot, systemd creates the service directories. The daemon creates a random instance ID atomically in persistent state on an installed system and a fresh ID in live RAM on each live boot. Give the local worker a stable ID derived from that instance and register it automatically once its capabilities and limits are known. Keep enrollment and credentials separate from graph state.
2. Run as an unprivileged dedicated UID. Use a group-restricted Unix socket with peer credentials and per-owner graph access. The console diagnostic client can request a redacted health report. The optional dashboard listens on loopback and accesses the same API with explicitly scoped authority.
3. Load unresolved assignments from SQLite before admitting work. Preserve attempt UUIDs, deadlines and revisions. Check cancellation tombstones and query a worker before retrying an ambiguous dispatch. Recompute expected reference operations and publish only validated output associated with the current attempt. Release slots on confirmed termination. Keep unreachable slots quarantined until reconciliation.
4. Run workers under supervised processes with a small fixed operation registry. Use systemd cgroup v2 CPUQuota, MemoryHigh, MemoryMax and TasksMax and keep OS I/O policy in systemd. Measure limits under pressure. Match capacity labels to applied limits. Use service hardening for filesystem writes, a private temporary directory, and a restricted capability set. Initially reserve one active attempt per worker and bound graph inputs, output, time and queue length.
5. On shutdown stop admitting graphs, persist outstanding state, request cancellation or bounded drain, and let systemd terminate remaining local processes. Size TimeoutStopSec from measured cleanup time. Restart on failure with a rate limit and report health from database readiness, worker checks and quarantine counts. Back up SQLite using its backup interface before schema migration and include referenced artifact data in snapshots.

Remote enrollment is operator opt-in. Exchange and verify the worker's host fingerprint independently, register a dedicated identity and role, and bind authorization to the chosen worker and operation set. Use the Phase 1B pinned SSH relay with fixed command, no TTY or forwarding and bounded messages. Track capabilities, last successful contact and measured RTT. Failed or offline remote placements can fall back only when the graph permits an eligible local placement. Disable inbound service by default. The earlier Linux SSH preflight remains blocked. Before enabling physical enrollment, demonstrate effective access restrictions, source-address enforcement, write scope and restart/cleanup on an isolated Linux OpenSSH server. Keep enrolled hosts and credentials out of the build.

Measure cold start, idle and peak memory, graph queue delay, per-attempt execution and transport time, correctness, and recovery latency. Log identifiers and timings without prompts or credentials.
